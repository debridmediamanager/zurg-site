01 / What it does

One folder.
Every account.

Two accounts. One library.

The same film on two services shows up once. If one account is busy or rate limited zurg reads from the other.

Add as many accounts as you own. There is no main account. Two more use about 5 MB of memory.

It plays the awkward stuff.

RAR and 7z releases play without unpacking. Scrambled filenames get their real names back. Missing pieces are rebuilt while you watch.

RAR 7z repairs damage unscrambles names

It fixes itself.

Real-Debrid links can go stale. zurg replaces dead links before playback fails. If one account loses a release it checks your other accounts for a cached copy.

Nothing is downloaded again. Services that make a fresh link each time have nothing to repair.

05 / Honest limits

The things it will not do.

Read these limits before you set it up. Every line comes from the same measurements as the rest of the page.

A broken release stays broken.

zurg rebuilds what the parity files can cover. Past that you get an empty folder rather than an error. There is nothing left to serve.

It finds out by trying.

zurg checks a release when you open it. A bad one is not skipped in advance.

The first build takes a while.

The first build is slow by design. Real-Debrid takes about half a second per torrent. After that zurg keeps up on its own.

Where that number comes from →

One box and one provider.

Everything was measured on one two core server with one news account. A different machine or backbone will change the numbers. Runs from different days do not compare.

These are our own numbers.

zurg is built by the person who ran the benchmark. Treat these as reference numbers. Your machine and connection will differ. zurg ships the same measurement as a command.
